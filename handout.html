Skills

Skills einrichten

Ein Skill ist eine Markdown-Datei mit Anweisungen, die der Agent befolgt. Er besteht aus YAML-Frontmatter (Metadaten) und einem Markdown-Body (die Anweisungen selbst).

Claude Code

▶

Wo liegen die Dateien?

ScopePfad
Projekt.claude/skills/<skill-name>/SKILL.md
Persönlich~/.claude/skills/<skill-name>/SKILL.md

Frontmatter-Felder

FeldBeschreibung
nameName des Slash-Commands (z.B. commit ergibt /commit)
descriptionWann der Skill geladen werden soll (wird dem Agent angezeigt)
disable-model-invocationtrue = nur manuell per /name aufrufbar
toolsWerkzeuge, die der Skill nutzen darf (z.B. Read, Bash)
contextfork = läuft in eigenem Sub-Agent

Beispiel

.claude/skills/email-schreiber/SKILL.md
--- name: email-schreiber description: Schreibt professionelle E-Mails. Verwende diesen Skill, wenn eine E-Mail geschrieben werden soll. --- # E-Mail schreiben Schreibe eine professionelle E-Mail nach diesen Regeln: 1. Beginne mit "Hallo [Name]," 2. Maximal 5 Sätze im Hauptteil 3. Ende mit "Viele Grüße"

Testen

Entweder per Slash-Command: /email-schreiber
Oder einfach fragen — der Agent erkennt anhand der description, wann der Skill passt.

Sub-Agents

Sub-Agents einrichten

Ein Sub-Agent ist ein spezialisierter KI-Assistent mit eigenem System-Prompt, eigenen Werkzeugen und eigenem Modell. Er läuft in einem eigenen Kontext.

Claude Code

▶

Wo liegen die Dateien?

ScopePfad
Projekt.claude/agents/<name>.md
Persönlich~/.claude/agents/<name>.md

Frontmatter-Felder

FeldPflichtBeschreibung
nameJaEindeutiger Name (Kleinbuchstaben, Bindestriche)
descriptionJaWann der Agent eingesetzt werden soll
toolsNeinErlaubte Werkzeuge (z.B. Read, Grep, Glob, Bash). Ohne Angabe: alle
disallowedToolsNeinVerbotene Werkzeuge (z.B. Write, Edit)
modelNeinsonnet, opus, haiku oder inherit (Standard)
memoryNeinuser, project oder local — persistenter Speicher über Sessions hinweg
backgroundNeintrue = läuft im Hintergrund

Beispiel

.claude/agents/korrekturleser.md
--- name: korrekturleser description: Prüft Texte auf Rechtschreibung und Grammatik. tools: Read, Grep, Glob model: sonnet --- Du bist ein erfahrener Korrekturleser. Prüfe Texte auf Fehler und gib Korrekturvorschläge. Verändere den Text NICHT selbst.

Aufrufen

Claude delegiert automatisch, wenn die Aufgabe zur description passt. Oder explizit mit @korrekturleser im Chat. Oder per /agents verwalten.

Beispiel

MCP-Server

MCP-Server einrichten

Ein MCP-Server ist ein kleines Programm, das zwischen eurem KI-Tool und einem externen Dienst (z.B. Jira, Figma, Slack) vermittelt. So bekommt der Agent Zugang zu Systemen, auf die er sonst keinen Zugriff hätte.

Allgemeines Vorgehen

  • Suchen: Auf GitHub oder npm nach einem MCP-Server für euren Dienst suchen
  • README lesen: Dort steht der Startbefehl und welche API-Keys/Tokens ihr braucht
  • Konfigurieren: Den Server in die Konfigurationsdatei eures Tools eintragen
  • Neu starten: Tool neu starten, damit der MCP-Server verbunden wird
  • Testen: Dem Agenten eine Frage stellen, die den externen Dienst braucht

Claude Code

▶

Konfigurationsdatei

ScopePfad
Projekt.mcp.json im Projektstamm
PersönlichGespeichert in ~/.claude.json (via claude mcp add)

Format

// .mcp.json (im Projektstamm) { "mcpServers": { "name-des-servers": { "type": "stdio", "command": "npx", "args": ["paketname"], "env": { "API_KEY": "euer-api-key" } } } }

Oder per CLI: claude mcp add name-des-servers --transport stdio -- npx paketname

Copilot CLI

▶

Konfigurationsdatei

ScopePfad
Persönlich~/.copilot/mcp-config.json

Alternativ per interaktivem Befehl: /mcp add

Format

// ~/.copilot/mcp-config.json { "mcpServers": { "name-des-servers": { "type": "local", "command": "npx", "args": ["paketname"], "env": {}, "tools": ["*"] } } }

Servertypen: local/stdio für lokale Prozesse, http/sse für Remote-Server. tools auf ["*"] für alle, oder spezifische Tool-Namen als Liste.

Cursor

▶

Konfigurationsdatei

ScopePfad
Projekt.cursor/mcp.json
Persönlich~/.cursor/mcp.json

Format

// .cursor/mcp.json { "mcpServers": { "name-des-servers": { "command": "npx", "args": ["paketname"], "env": { "API_KEY": "${env:MY_API_KEY}" } } } }

Tipp: Cursor unterstützt ${env:NAME} um Secrets aus Umgebungsvariablen zu lesen, statt sie direkt in die Datei zu schreiben.

Codex CLI

▶

Konfigurationsdatei

ScopePfad
Projekt.codex/config.toml
Persönlich~/.codex/config.toml

Format (TOML)

# .codex/config.toml [mcp_servers.name-des-servers] command = "npx" args = ["paketname"] env = { API_KEY = "euer-api-key" } enabled = true

Hinweis: Codex nutzt TOML statt JSON. API-Keys können auch über eine Umgebungsvariable referenziert werden: bearer_token_env_var = "MY_API_KEY".
