Let's Code

Context Engineering — Übungen

Hier könnt ihr Skills, Sub-Agents und MCP-Server selbst ausprobieren. Ihr braucht dafür kein Programmierwissen — nur ein Tool eurer Wahl (Claude Code, Cursor, Copilot oder Codex CLI) und Lust zum Experimentieren.

1

Skills — Eigene Rezepte schreiben

Ein Skill ist eine Textdatei mit Anweisungen, die der KI-Agent befolgt. Wie ein Rezept: einmal geschrieben, immer wieder nutzbar.

📧

E-Mail-Schreiber Nicht-Techies · Einstieg

Erstellt einen Skill, der professionelle E-Mails in eurem Unternehmensstil schreibt.

  1. Legt die Datei .claude/skills/email-schreiber/SKILL.md an
  2. Schreibt Frontmatter mit Name und Beschreibung
  3. Definiert Regeln: Anrede, Tonalität, Signatur, max. Länge
  4. Testet den Skill: „Schreibe eine E-Mail an einen Kunden, der nach dem Projektstand fragt."
--- name: email-schreiber description: Schreibt professionelle E-Mails im lise-Stil. --- # E-Mail schreiben Schreibe eine professionelle E-Mail nach diesen Regeln: 1. Beginne mit "Hallo [Name]," — kein "Sehr geehrte/r" 2. Halte den Ton freundlich, aber professionell 3. Maximal 5 Sätze im Hauptteil 4. Ende mit "Viele Grüße" und dem eigenen Namen 5. Vermeide Floskeln wie "hiermit" oder "bezugnehmend auf"
Tipp: Probiert danach verschiedene Szenarien — Absage, Terminvorschlag, Nachfrage. Ist das Ergebnis jedes Mal im richtigen Stil?
📱

Social-Media-Post-Generator Nicht-Techies · Fortgeschritten

Erstellt einen Skill, der aus einem Thema einen LinkedIn-Post im Unternehmensstil generiert.

  1. Legt .claude/skills/linkedin-post/SKILL.md an
  2. Definiert Stil-Regeln: Länge, Tonalität, Hashtags, Zielgruppe
  3. Fügt ein Beispiel hinzu, wie ein guter Post aussehen soll
  4. Testet: „Schreibe einen LinkedIn-Post über unsere neue Partnerschaft mit Microsoft."
Bonus: Könnt ihr den Skill so erweitern, dass er verschiedene Plattformen unterstützt? Z.B. per Argument: /linkedin-post Twitter
💬

Commit-Message-Skill Techies · Einstieg

Erstellt einen Skill, der standardisierte Commit-Messages nach euren Team-Konventionen generiert.

  1. Legt .claude/skills/commit/SKILL.md an
  2. Definiert Regeln: Sprache, Format, maximale Länge, Präsens vs. Vergangenheitsform
  3. Fügt hinzu, dass vor dem Commit Tests laufen sollen
  4. Testet: Macht eine kleine Änderung und sagt „Committe das"
Tipp: Setzt disable-model-invocation: true im Frontmatter — dann wird der Skill nur manuell per /commit ausgelöst, nicht automatisch.
🚀

PR-Ersteller mit dynamischem Kontext Techies · Fortgeschritten

Erstellt einen Skill, der automatisch eine Pull Request mit Zusammenfassung und Testplan erstellt — basierend auf den aktuellen Änderungen.

  1. Legt .claude/skills/create-pr/SKILL.md an
  2. Nutzt dynamischen Kontext: Der Skill soll per !`git diff` und !`git log` die aktuellen Änderungen einlesen, bevor er losarbeitet
  3. Definiert ein PR-Format: Zusammenfassung, Änderungen, Testplan
  4. Setzt context: fork, damit der Skill in einem eigenen Sub-Agent läuft
  5. Testet: Macht Änderungen auf einem Branch und sagt „/create-pr"
Tipp: Die !`befehl`-Syntax führt Shell-Befehle aus, bevor der Skill-Inhalt an den Agent geschickt wird. So hat er automatisch den aktuellen Diff als Kontext.

Sub-Agents — Eigene Spezialisten bauen

Ein Sub-Agent ist ein Spezialist mit eigenem Wissen, eigenen Werkzeugen und eigenem Verhalten. Wie ein Kollege, der genau weiß, was er tun soll.

🔍

Korrekturleser Nicht-Techies · Einstieg

Erstellt einen Sub-Agent, der Texte auf Fehler prüft — ohne sie zu verändern.

  1. Legt .claude/agents/korrekturleser.md an
  2. Gebt ihm nur Lese-Rechte: tools: Read, Grep, Glob
  3. Schreibt einen System-Prompt, der beschreibt, worauf er achten soll
  4. Testet: „Prüfe die Datei angebot.md auf Rechtschreibfehler und unklare Formulierungen."
--- name: korrekturleser description: Prüft Texte auf Rechtschreibung, Grammatik und verständliche Formulierungen. Verwende bei Textprüfungen und vor dem Versenden von Dokumenten. tools: Read, Grep, Glob model: sonnet --- Du bist ein erfahrener Korrekturleser für Geschäftstexte. ## Vorgehen 1. Lies den gesamten Text 2. Prüfe Rechtschreibung und Grammatik 3. Prüfe auf unklare oder umständliche Formulierungen 4. Gib eine Liste aller Fundstellen mit Korrekturvorschlag ## Regeln - Verändere den Text NICHT selbst - Gib zu jedem Fehler die Zeile und den Korrekturvorschlag an - Unterscheide: Fehler / Stilverbesserung / Vorschlag
Tipp: Durch tools: Read, Grep, Glob kann der Agent Dateien lesen, aber nicht verändern — so geht nichts kaputt.
📊

Angebots-Prüfer Nicht-Techies · Fortgeschritten

Erstellt einen Sub-Agent, der Angebotsdokumente auf Vollständigkeit und Konsistenz prüft.

  1. Legt .claude/agents/angebots-pruefer.md an
  2. Definiert eine Checkliste: Ist ein Datum vorhanden? Stimmen die Summen? Fehlt die Unterschrift?
  3. Gebt ihm Lese-Zugriff und Bash (damit er rechnen kann)
  4. Testet ihn mit einem Beispiel-Angebot
Bonus: Fügt memory: project hinzu — dann merkt sich der Agent über mehrere Sessions hinweg, welche Fehler häufig vorkommen.
🔎

Code-Reviewer Techies · Einstieg

Erstellt einen Sub-Agent, der Code-Änderungen auf Qualität und Best Practices prüft — ohne selbst etwas zu ändern.

  1. Legt .claude/agents/code-reviewer.md an
  2. Gebt ihm nur Lese-Zugriff und Bash (für git diff): tools: Read, Grep, Glob, Bash
  3. Schreibt einen System-Prompt mit einer Review-Checkliste: Lesbarkeit, Sicherheit, Fehlerbehandlung, Tests
  4. Definiert ein Ausgabeformat: Kritisch / Warnung / Vorschlag
  5. Testet: Macht eine Änderung und sagt „Reviewe meine letzten Änderungen"
Tipp: Da der Agent kein Edit oder Write hat, kann er nur Feedback geben — nicht versehentlich euren Code verändern.
🐛

Debugger mit Memory Techies · Fortgeschritten

Erstellt einen Sub-Agent, der Fehler analysiert, Fixes vorschlägt und sich über Sessions hinweg merkt, welche Probleme häufig auftreten.

  1. Legt .claude/agents/debugger.md an
  2. Gebt ihm volle Werkzeuge: tools: Read, Edit, Bash, Grep, Glob
  3. Schreibt einen Prompt mit einem klaren Debugging-Ablauf: Fehler erfassen, reproduzieren, Root Cause finden, Fix implementieren, verifizieren
  4. Aktiviert persistenten Speicher mit memory: project
  5. Testet ihn mehrmals — nach ein paar Sessions sollte er häufige Fehlerquellen in eurem Projekt kennen
Tipp: Fügt in den System-Prompt die Anweisung ein, dass der Agent nach jedem Debugging sein Memory aktualisieren soll. So baut er über die Zeit Wissen über euer Projekt auf.

MCP-Server — Externe Werkzeuge anbinden

MCP-Server geben dem KI-Agenten Zugang zu externen Systemen — wie ein Handy, mit dem er nachschlagen und kommunizieren kann. Ohne MCP-Server kennt der Agent nur Dateien und das Terminal. Mit MCP-Server kann er z.B. Jira-Tickets lesen oder Figma-Designs abrufen.

📖

Wie funktioniert ein MCP-Server?

Ein MCP-Server ist ein kleines Programm, das zwischen eurem KI-Tool und einem externen Dienst vermittelt. So funktioniert das Einrichten:

  1. MCP-Server finden: Sucht auf GitHub oder npm nach einem MCP-Server für euren Dienst (z.B. „jira mcp server" oder „figma mcp server")
  2. Konfiguration eintragen: Tragt den Server in die Konfigurationsdatei eures Tools ein — das ist eine JSON-Datei mit dem Startbefehl und ggf. API-Keys
  3. Tool neu starten: Nach dem Speichern der Konfiguration das Tool neu starten — der MCP-Server wird automatisch verbunden
  4. Testen: Stellt dem Agenten eine Frage, die den externen Dienst braucht

Die Konfigurationsdatei sieht bei allen Tools ähnlich aus:

// Beispiel-Struktur (die konkreten Werte findet ihr // in der Doku des jeweiligen MCP-Servers) { "mcpServers": { "name-des-servers": { "type": "stdio", "command": "npx", // oder uvx, node, python ... "args": ["paketname"], // aus der Doku des Servers "env": { "API_KEY": "euer-key" // falls der Dienst einen braucht } } } }

Wo kommt das hin?

  1. Claude Code: .claude/settings.json
  2. GitHub Copilot: .vscode/settings.json
  3. Cursor: .cursor/mcp.json
  4. Codex CLI: .codex/config.toml
🎨

Figma anbinden Für Designer & Nicht-Techies

Gebt eurem Agenten Zugriff auf eure Figma-Designs — damit er z.B. Farben, Abstände oder Texte direkt aus Figma lesen kann.

Eure Aufgabe: Findet selbst heraus, wie man einen Figma-MCP-Server einrichtet, konfiguriert ihn und testet ihn.

Ziel: Am Ende könnt ihr dem Agenten sagen: „Welche Farben werden in meinem Figma-Design verwendet?" — und er antwortet mit echten Daten aus Figma.
